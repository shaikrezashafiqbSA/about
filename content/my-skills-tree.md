## **How to use this file**

### **Usage rules**

* Never submit this file. It is a retrieval database for the resume, not the resume.
* Every tailored resume sources its facts from the evidence units (EU) below. Cite EU IDs during tailoring so claims stay traceable.
* Never change a metric in this file without a source record. Tailored resumes may rephrase to align with Job Description language; they may not re-quantify.
* Variant framings are labelled by source resume.
* New experiences surfaced by the job-match pipeline are appended as new EU entries. Do not overwrite existing entries; supersede them.
* Where an EU carries a "Claim boundary" note, the boundary is binding. It records the honest limit of the claim.
* An EU ID is never reused or renumbered. A moved or retired unit keeps its ID, so older tailored resumes still resolve to the right unit.
* This file is public. Contact details, Interview notes, Claim boundaries, Tailoring notes, reasons for leaving and the Tailored Resume Structure live in content/private/private-notes.md (gitignored, never published), under the same EU IDs and headings. Read both files when tailoring. Never add private material to this file.

### **Evidence unit fields**

Every EU sits under its own heading, `EU-<ROLE>-<NN> · Title`, followed by the fields below in this order. A field is left out when it has nothing to say.

| Field | What it holds | Tailoring use |
| :---- | :---- | :---- |
| Tags | Competency codes from the taxonomy | Match to JD vocabulary; never print on a resume |
| Scale and tools | Numbers, systems, tools, sources | Specifics for bullets and the skills line |
| Canonical | Fullest defensible wording | Rephrase freely; never re-quantify |
| Variants | Framings from V-PM, V-AUTO, V-SUPPORT, V-OPS | Pick the one closest to the JD |
| Wording variant | Approved alternative phrasing for a JD type | Use as written |
| Claim boundary | Honest limit, with approved and banned forms | Binding |
| Interview notes | Arithmetic, starting state, basis of a claim | Interview only; not for resumes |
| Relationship | How this unit pairs with another | Never present paired units as separate achievements |

Role prefixes: NHB (National Heritage Board), EKK (EkkBaz AI), CL (Call Levels), AS (Alpha Stone Capital), GIC, XR (cross-role), NS (National Service), CIMB (CGS-CIMB), SIN (Singtel), EDU (community education), APP (community application).

### **Skill tree use**

This file also feeds the skill tree on the GitHub about page (web/skills.html). The tree reads the same evidence units. Nothing in this subsection changes the tailoring rules above.

* **Metrics:** optional EU field, placed after Scale and tools (or after Tags when Scale and tools is absent). Holds the unit's quantified impact as approved display strings, separated by " | ". Every figure is drawn from the unit's Canonical, Scale and tools, Outcome or approved Claim boundary wording, never from Interview notes. Claim boundaries apply to Metrics exactly as they apply to Canonical. Tailoring may use Metrics as written.
* **Tree links:** optional EU field, placed last. Machine-readable form of the Relationship field. `merge EU-...` means the units render as one node and are never separate achievements. `link EU-...` means the tree draws a synergy line between them. Tree-only; never print on a resume.
* **Skills register columns:** ID, Family, Strength, Status and Icon are tree columns. The original "Claim strength and rule" column remains the binding rule for tailoring.
* **Skill tree configuration:** the final section of this file holds tree-only data (classes, attributes, region icons, keystones, growth targets). Ignore it when tailoring.
* **Appending a new EU:** add Metrics when the unit carries approved figures, add Tree links when it carries a Relationship, and add the EU ID to every matching row of the Skills register. A unit absent from the register appears in the tree's unassigned tray.
